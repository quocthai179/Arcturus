# Ngân sách tài nguyên

Đây là mục tiêu thiết kế, không phải số đo. Mọi PR đụng `crates/hub*` hoặc `crates/app` phải đo lại bằng `/budget-check`
và ghi kết quả vào bảng "Lịch sử đo" bên dưới.

## Mục tiêu

| Thành phần | RAM (RSS) | CPU khi rảnh | Ghi chú |
|---|---|---|---|
| Hub, 0 phiên | ≤ 15 MB | ≈ 0% | không timer nào chạy nhanh hơn 30 giây |
| Hub, 20 phiên hoạt động | ≤ 40 MB | < 1% | ring buffer sự kiện trong RAM tối đa 2.000 mục |
| App Lite (tray + popup đóng) | ≤ 60 MB | ≈ 0% | không giữ webview khi popup đóng |
| App Lite (popup mở) | ≤ 150 MB tổng, tính theo **private working set** | < 0,5% | working set cộng qua các tiến trình WebView2 đếm trùng trang dùng chung nên không dùng cho dòng này |
| Mở popup (đường chuột) | ≤ 300 ms | | con trỏ dừng ≥ ~0,5 s trên icon rồi bấm; popup được tạo sẵn (`tray.rs`, prewarm). Đo từ lúc bấm tới khung React đầu tiên |
| Mở popup (đường nguội) | ≤ 500 ms | | không tạo sẵn: bàn phím, cảm ứng, bấm ngay khi con trỏ vừa tới, mở lại ngay sau khi đóng; tạo webview WebView2 nguội ≈ 285 ms |
| Văn phòng 2D mở | + 50–80 MB | < 2% | 15 FPS khi có hoạt động, 0 khi tất cả rảnh hoặc ẩn |
| Độ trễ ingest | p99 ≤ 5 ms | | `/hooks/event` trả 204 ngay, xử lý sau |

## Cách đo

Dùng script (T16 · ARC-37): chúng chạy đúng kịch bản chuẩn bên dưới, ghi CSV `ts,rss_kb,cpu_pct,priv_kb,phase` vào
`target/measure/`, in một dòng tóm tắt `measure ... verdict=PASS|FAIL` và thoát mã 1 khi vượt ngân sách. Agent
`budget-guard` chạy chúng thay vì đo tay.

```bash
scripts/measure.sh                        # Linux/macOS: hub
pwsh scripts/measure.ps1                  # Windows: hub
pwsh scripts/measure.ps1 -Target app      # Windows: app bản release, đường nguội (tray, mở/đóng popup, thời gian mở popup)
pwsh scripts/measure.ps1 -Target app -HoverMs 500   # như trên nhưng mô phỏng con trỏ dừng 500 ms trên icon trước khi bấm (prewarm)
```

Chế độ đo của app (`crates/app/src-tauri/src/measure.rs`) chỉ bật khi script đặt `ARCTURUS_MEASURE_POPUP=<số lần>`: app tự
mở/đóng popup và ghi `[measure] event=...` ra stderr; `popup_ready` là thời gian từ lúc bắt đầu mở cửa sổ tới khung đầu
tiên đã vẽ. RSS là working set (Windows) hoặc VmRSS (Linux); app tính cả cây webview, không tính hub con. Riêng popup mở được so với
ngân sách theo **private working set** (cột `pws_kb`, `Win32_PerfFormattedData_PerfProc_Process.WorkingSetPrivate`), vì working set cộng qua nhiều
tiến trình đếm trùng trang dùng chung; `popup_open_rss_mb` vẫn được in để đối chiếu. `-HoverMs 500` (mặc định) mô phỏng con trỏ dừng 500 ms
trên icon (đường chuột, ≤300 ms); `-HoverMs 0` đo đường nguội (≤500 ms).

Kiểm tay bằng chuột thật (không tự động hoá): chạy app với `ARCTURUS_MEASURE_LOG=1` (chỉ ghi mốc ra stderr, không tự mở popup),
rê chuột ~0,5 s trên icon tray rồi bấm; stderr phải có `popup_prewarmed` rồi `popup_shown` và `popup_ready ms=<nhỏ>`:
`$env:ARCTURUS_MEASURE_LOG='1'; .\cratespp\src-tauri	arget
eleasercturus-app.exe 2>&1 | Select-String '\[measure\]'`.

Đo tay (khi cần soi một tiến trình):
- Linux/macOS: `pgrep -f 'target/.*/hub' | xargs -I{} ps -o pid,rss,%cpu,etime,command -p {}` (RSS bằng KB).
- Windows: `Get-Process hub, arcturus-app | Select-Object Name, Id, @{n='RSS_MB';e={[math]::Round($_.WorkingSet64/1MB,1)}}, CPU`.

Kịch bản chuẩn:
1. Khởi động hub, chờ 60 giây, đo (idle).
2. `cargo run --release -p replay -- fixtures/hooks --sessions 20 --rate 50 --duration 120 --permission-mode skip`, đo trong lúc chạy.
3. Dừng replay, chờ 60 giây, đo lại. RSS phải quay về gần mức idle (không rò rỉ).

Đo trên ít nhất một máy yếu (ví dụ 4 GB RAM, 2 nhân) trước mỗi mốc phát hành.
